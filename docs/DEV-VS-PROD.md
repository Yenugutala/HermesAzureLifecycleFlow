# DEV vs PROD

This document describes what changes between a local development setup and the production Azure deployment.

## Side-by-Side Comparison

| Aspect | Local DEV | Production |
|--------|-----------|------------|
| **control-plane** | `uvicorn main:app --port 3978 --reload` | Azure Container App, auto-scaled 0→3 replicas |
| **hermes-service** | `python main.py` | Azure Container App, queue-scaled 0→5 replicas |
| **Slack webhook URL** | `ngrok http 3978` → `https://<id>.ngrok.io/slack/events` | APIM gateway URL (permanent HTTPS) |
| **Teams webhook URL** | ngrok tunnel | APIM gateway URL |
| **Slack HMAC check** | In control-plane only | APIM pre-checks + control-plane double-checks |
| **Rate limiting** | None | APIM: 100 req/min per IP |
| **Correlation ID** | Generated in control-plane | Generated by APIM, passed to control-plane |
| **Secrets** | `.env` file | Azure Container App secrets (never in code) |
| **SessionDB location** | `~/.hermes/state.db` | Azure Files mount `/mnt/hermes-state/state.db` |
| **SessionDB persistence** | Deleted on OS restart / machine wipe | Persists across container restarts and redeployments |
| **HERMES_HOME** | `~/.hermes` (default) | `/mnt/hermes-state` (via `HERMES_HOME` env var) |
| **Logs** | Console (stdout) | Container Apps log stream + Log Analytics + App Insights |
| **Container images** | Run directly from source | Docker images in Azure Container Registry |
| **CI/CD** | Manual | GitHub Actions → ACR → Container Apps on every `main` push |
| **Service Bus tier** | Standard (shared with prod queue if using same `.env`) | Standard, dedicated namespace |
| **APIM tier** | Not used locally | Standard (2 units) |
| **App Insights** | Optional (console telemetry if no connection string) | Always on |
| **Azure Files SKU** | Not used | Premium_LRS |
| **Scaling** | Single process, no auto-scale | HTTP + queue-depth scale rules |

## What Is Identical in Both Environments

- Application code (`control-plane/main.py`, `hermes-service/main.py`)
- Hermes plugins (`plugins/*.py`)
- Hermes toolsets (`hermes.yaml`)
- RBAC logic (`capabilities.py`)
- Jira + Confluence API calls
- LLM model and fallback chain
- Skills files (`~/.hermes/skills/`)
- The Service Bus queue name

## Running Both Services Locally

```bash
# Terminal 1 — control-plane
cd control-plane
source ../.venv311/bin/activate
uvicorn main:app --host 0.0.0.0 --port 3978 --reload

# Terminal 2 — hermes-service
cd hermes-service
source ../.venv311/bin/activate
python main.py

# Terminal 3 — ngrok (for Slack webhook testing)
ngrok http 3978
# Copy the https URL → Slack app Event Subscriptions Request URL
```

## Simulating Prod Locally with Docker

```bash
# Build images
docker build -t control-plane:dev ./control-plane
docker build -t hermes-service:dev ./hermes-service

# Run control-plane
docker run --rm --env-file .env -p 3978:3978 control-plane:dev

# Run hermes-service
docker run --rm --env-file .env hermes-service:dev
```

## Promoting a Change from DEV to PROD

1. Test your change locally (see above)
2. Push to a feature branch: `git push origin feat/<your-change>`
3. Open a pull request against `main`
4. Merge to `main` → GitHub Actions automatically builds + deploys to prod
5. Verify in App Insights or `az containerapp logs show`
